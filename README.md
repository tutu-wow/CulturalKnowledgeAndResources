# 历史文化知识普及与资源管理系统

> 系统亮点：DeepSeek流式AI问答、协同过滤推荐、ECharts数据看板、历史文化图文与视频资源管理、文化活动报名审核及签到码签到、收藏评论与意见反馈；

## 一、项目概述

历史文化知识普及与资源管理系统采用前后端分离架构，面向普通用户和管理员构建“文化资源展示—内容检索—收藏评论—活动报名—审核签到—反馈处理—智能问答”的服务流程。普通用户可浏览历史文化知识、宣传视频、文化资讯、文化活动和公告，按名称或分类筛选资源，在历史文化知识和宣传视频详情中发表评论，并对历史文化知识、宣传视频和文化资讯进行收藏；用户还可报名参与文化活动，在个人中心查看报名状态、签到码及签到时间，提交意见反馈并查看平台回复。管理员负责用户账号、历史文化知识及分类、宣传视频、文化资讯及分类、轮播图、文化活动、活动报名、评论、收藏、公告、反馈和 AI 问答记录的统一维护，并通过数据看板查看资源数量、用户注册趋势、知识分类分布及热门资源情况。

## 二、技术架构

| 层级 | 主要技术与职责 |
| :--- | :--- |
| 用户服务端 | 基于 Vue 3、Vite、Element Plus、Pinia、Vue Router 和 Axios 构建，提供知识、视频、资讯、活动、公告、收藏、评论、反馈、个人中心和 AI 问答等功能。 |
| 管理工作台 | 基于 Vue 3、Element Plus 和 ECharts 实现，维护账号、资源、活动报名、互动数据与公告反馈，查看统计看板。 |
| 服务端 | 基于 Spring Boot 3、Java 17、Spring MVC、MyBatis-Plus、MySQL 和 JWT 提供 REST 接口、分页查询、文件上传与统一异常处理。 |
| 智能与推荐能力 | 接入 DeepSeek 对话接口，SSE 持续返回回答片段；基于收藏与评论的余弦相似度做协同过滤推荐。 |

## 三、核心功能与实现说明

### 3.1 双角色认证、账号维护与页面访问控制
系统设置管理员和普通用户两类角色。用户使用账号、密码和角色登录后，服务端校验账号信息并签发包含用户标识和角色标识的 JWT；前端保存登录状态，并在后续请求中携带 Token。服务端拦截器解析请求头中的 Token，将当前用户信息写入上下文；前端路由依据角色决定进入管理工作台或用户服务端。普通用户可完成注册、个人资料维护、密码修改和密码找回；管理员可按账号、昵称、邮箱、手机号和角色查询用户，并进行账号新增、编辑、密码重置、单条或批量删除及 Excel 导出。

注册或登录 → 服务端校验账号与角色 → 签发 JWT → 前端保存登录状态 → 请求携带 Token → 服务端解析当前用户 → 前端按角色进入对应功能页面

| **业务场景** | **系统处理结果** |
| :--- | :--- |
| 身份认证 | 登录成功后返回 JWT，Token 中保存用户 ID 与角色信息；当前用户拦截器从请求头解析 Token，并将用户 ID 和角色写入当前请求上下文。 |
| 用户注册 | 注册时校验账号唯一性；填写邮箱或手机号时，系统分别校验邮箱、手机号是否重复，密码经 MD5 处理后写入账号数据。 |
| 个人资料与密码 | 用户可在个人中心修改昵称、头像、邮箱和手机号，修改密码时校验原密码；找回密码时校验账号、已绑定手机号及已填写的邮箱信息。 |
| 后台账号管理 | 管理员可按账号、昵称、邮箱、手机号和角色分页查询账号，查询结果不返回密码字段，并支持重置密码和导出账号列表。 |

### 3.2 历史文化资源分类、内容发布与多媒体展示
平台以历史文化知识为核心资源，管理员先维护分类名称、分类描述和排序，再录入历史文化知识的名称、分类、封面、图片集、起源地、年代、传承人、详细介绍、上架状态和浏览量等信息。普通用户可按名称和分类筛选已上架的历史文化知识，在详情页查看图文介绍和图片集。宣传视频可关联具体历史文化知识，维护视频标题、封面、视频地址、简介、播放量和上架状态，用户可在视频详情页在线播放。文化资讯支持按资讯类型维护标题、正文、封面、作者、发布时间和浏览量；首页同时汇总轮播图、公告、热门历史文化知识、热门视频、最新资讯与文化活动，为用户提供内容入口。

维护资源分类 → 录入历史文化知识、视频和资讯内容 → 配置封面、图片或视频地址及上架状态 → 用户在首页或分类列表浏览与筛选 → 进入详情页查看图文或播放视频

| **资源场景** | **系统处理结果** |
| :--- | :--- |
| 历史文化知识分类 | 分类保存名称、描述和排序；历史文化知识关联所属分类，前台列表可按分类筛选，后台可统一维护分类与资源内容。 |
| 图文资源展示 | 历史文化知识保存封面、图片集、起源地、年代、传承人、详细介绍、上架状态和浏览量；前台仅加载已上架资源，并在列表和详情页展示对应信息。 |
| 宣传视频 | 视频记录可关联历史文化知识，包含封面、视频地址、简介、播放量和上架状态；视频详情页使用浏览器视频控件播放资源。 |
| 资讯与首页聚合 | 文化资讯关联资讯分类并保存作者、发布时间和浏览量；首页加载轮播图、公告、热门知识与视频、最新资讯和文化活动，展示各类资源总量。 |

### 3.3 收藏评论、个人中心与协同过滤推荐
用户可对历史文化知识、宣传视频和文化资讯执行收藏或取消收藏操作，收藏记录保存用户、目标标识和目标类型；个人中心将收藏记录集中展示。历史文化知识和宣传视频详情页提供评分评论入口，评论记录保存用户、目标、目标类型、内容和评分，后台评论管理可关联展示评论用户及目标资源的名称、封面。针对历史文化知识，系统基于用户收藏和评论行为构建用户—资源评分矩阵，其中收藏权重为 3、评论权重为 2；系统计算用户间的余弦相似度，选择相似度最高的 5 名用户，将其接触而当前用户未接触的资源按加权分数排序推荐。用户没有行为数据、没有相似用户或推荐数量不足时，则按历史文化知识的浏览量补充热门资源。

用户收藏或评论历史文化知识 → 写入目标类型与目标标识 → 构建用户—资源评分矩阵 → 计算余弦相似度 → 选择相似用户的未接触资源 → 热门资源补足推荐结果

| **互动与推荐场景** | **系统处理结果** |
| :--- | :--- |
| 收藏管理 | 收藏接口按用户、目标和目标类型检查已有记录；存在时取消收藏，不存在时新增收藏，用户可在个人中心查看自己的收藏内容。 |
| 评分评论 | 历史文化知识和宣传视频详情页支持用户提交 1 至 5 星评分及评论内容，评论列表按目标加载并展示评论用户与评分信息。 |
| 协同过滤推荐 | 推荐仅面向历史文化知识，使用收藏和评论两类行为计算评分与余弦相似度，最多选取 5 个相似用户，并输出不超过 8 条推荐资源。 |
| 热门资源兜底 | 当当前用户没有相关行为、没有相似用户或个性化结果不足时，系统从已上架历史文化知识中按浏览量降序选取热门资源补充结果。 |

### 3.4 文化活动发布、在线报名、审核与签到
管理员可维护文化活动名称、图文内容、封面、图片集、地点、活动起止时间、报名人数上限、活动状态、坐标及报名起止时间。用户可在活动列表按名称、地点和状态检索活动，并在详情页查看报名时间、活动时间、地点、人数上限、坐标和图文介绍。前端根据当前时间与报名、活动时间动态显示“报名中、进行中、已结束”状态；活动处于报名期时，登录用户可提交待审核的报名记录，系统同时生成签到码。管理员可对待审核报名执行通过或拒绝，对已通过报名输入正确签到码后完成签到；用户可在个人中心查看自己的报名状态、签到码、审核时间、签到时间，并可取消待审核或已通过的报名。

管理员发布活动与报名时间 → 用户浏览活动详情并报名 → 创建待审核报名记录和签到码 → 管理员审核通过或拒绝 → 对已通过记录验证签到码 → 更新为已签到 → 用户在“我的活动”查看记录

| **活动环节** | **系统处理结果** |
| :--- | :--- |
| 活动发布与查询 | 活动保存图文内容、时间、地点、人数上限、坐标及报名时间；后台支持按名称、地点、状态和时间范围分页查询与维护，前台提供名称、地点和状态检索。 |
| 报名状态展示 | 活动详情页依据当前时间和配置的报名、活动时间计算展示状态，仅在报名期开放报名按钮；用户报名后前端通过报名记录判断该活动是否已报名。 |
| 审核与取消 | 报名记录状态包含待审核、已通过、已拒绝、已签到和已取消；管理员仅能审核待审核记录，系统仅允许取消待审核或已通过的记录。 |
| 签到码验证 | 签到时系统校验报名记录存在、当前状态为已通过、签到码已生成且与输入值一致；校验通过后写入签到时间并将报名状态更新为已签到。 |

### 3.5 公告轮播、意见反馈与处理记录
管理员可维护首页轮播图和公告内容。轮播图保存标题、图片地址和排序，用于首页轮播展示；公告保存标题、正文、公告类型、发布时间和发布人，用户可在公告列表分页查看并通过弹窗阅读详细内容。用户可提交带标题、详细内容和可选图片附件的意见反馈，反馈初始状态为待处理；管理员回复后，系统保存回复内容和回复时间，并将状态更新为已回复。用户可在个人中心集中查看自己的反馈及平台回复，后台可按标题、用户、状态和回复时间检索反馈记录。

管理员维护轮播图和公告 → 首页与公告页加载展示 → 用户提交图文反馈 → 创建待处理记录 → 管理员填写回复 → 更新反馈状态与回复时间 → 用户在个人中心查看处理结果

| **服务场景** | **系统处理结果** |
| :--- | :--- |
| 轮播与公告 | 首页按分页加载轮播图和公告，轮播图展示标题和图片；公告列表显示发布时间，用户点击后在详情弹窗中查看公告正文。 |
| 反馈提交 | 反馈表单校验标题和内容，可附加图片；提交时关联当前用户，初始状态为待处理。 |
| 反馈回复 | 管理员对指定反馈填写回复内容后，服务端写入回复时间并将反馈状态修改为已回复。 |
| 个人反馈记录 | 个人中心按当前用户分页加载反馈记录，展示反馈标题、内容、处理状态、平台回复及回复时间。 |

### 3.6 DeepSeek 历史文化问答与流式记录
平台接入 DeepSeek 模型，提供历史文化、非遗文物和传统技艺相关的 AI 问答服务。用户提交问题后，服务端查询已上架且浏览量靠前的历史文化知识，并读取现有分类信息，将资源名称、年代、起源地、传承人和简介等内容组织为系统提示词；随后将提示词和用户问题发送至 DeepSeek 接口。模型返回内容以 SSE 事件流持续推送，前端逐段拼接并显示回答，无需等待完整回答生成。生成结束后，服务端在用户标识存在且回答内容非空时保存提问、完整回答和用户信息，管理员可在后台查询和维护 AI 问答记录。

用户输入问题 → 查询已上架历史文化知识与分类 → 组装平台知识提示词 → 调用 DeepSeek 流式接口 → SSE 持续推送回答片段 → 前端逐段展示 → 保存本次问答记录

| **问答环节** | **系统处理结果** |
| :--- | :--- |
| 知识提示词构建 | 服务端从已上架历史文化知识中按浏览量读取最多 20 条，并补充资源分类信息，形成面向历史文化场景的系统提示词。 |
| 流式回答 | 后端以 SSE 响应方式读取 DeepSeek 返回的内容片段并即时转发，前端通过流式读取逐段拼接展示答案。 |
| 异常反馈 | 当模型接口返回非成功状态或发生网络异常时，服务端向前端返回对应的暂不可用或网络异常提示，并结束本次事件流。 |
| 问答记录 | 服务端保存本次问题、完整回答和用户标识，回答内容超过 5000 个字符时截取后保存；后台提供 AI 问答记录的分页查询与维护入口。 |

### 3.7 ECharts 数据看板与后台综合维护
管理员首页提供数据看板，展示历史文化知识、宣传视频、普通用户和文化活动的总量。看板通过查询历史文化知识分类及其资源数量生成分类分布饼图；通过读取普通用户创建时间统计最近 7 天注册趋势；同时按历史文化知识和宣传视频的浏览量字段排序，展示热门知识科普 TOP10 与热门视频 TOP10。管理工作台还将账号、资源、活动报名、评论、收藏、反馈、公告和 AI 问答记录纳入统一菜单，列表页面提供条件查询、分页、新增、编辑、删除或批量删除等相应维护能力。

加载资源、用户与活动总数 → 查询分类及分类下资源数量 → 统计最近 7 天用户创建数据 → 按浏览量排序热门资源 → ECharts 渲染图表 → 管理员进入各业务列表维护平台数据

| **管理能力** | **系统处理结果** |
| :--- | :--- |
| 总量概览 | 看板加载历史文化知识、宣传视频、普通用户和文化活动的总数量，作为后台首页的基础概览数据。 |
| 分类与注册趋势 | 系统按历史文化知识分类统计资源数量并绘制环形饼图；根据普通用户创建时间聚合最近 7 天数据并绘制注册趋势折线图。 |
| 热门资源排行 | 看板按历史文化知识和宣传视频的浏览量字段降序获取前 10 条数据，并以横向柱状图展示热门内容。 |
| 统一后台维护 | 管理员可通过后台菜单进入账号、分类、历史文化知识、视频、资讯、轮播图、活动报名、评论、收藏、反馈、公告和 AI 问答记录等模块进行维护。 |
